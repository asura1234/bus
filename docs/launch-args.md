# Agent launch arguments

## Interactive provider launch

Provider add, resume and native restart share one interactive-shell launch path.
Bus-created zsh, bash, fish and PowerShell panes retain normal prompt hooks
(including direnv) and shell functions. Bus waits for its private primary-editor
readiness mark, verifies the editable command buffer before Enter, and corrects
a damaged paste once before verifying it again. A line that cannot be verified
is left unsubmitted with the pane retained for inspection. An existing pane
without Bus integration receives no launch input; create a new Bus-owned pane
instead. Plain sh/dash and shells without a supported line editor fail before
input with guidance to use one of the supported shells.

A confirmed startup failure closes sender-authored requests that never reached
provider input as `agent_startup_failed`; async waits return `message_abandoned`.
Bus retains their message IDs and failure detail so the sender can inspect and
explicitly resend after repairing the agent. Other confirmed missing or replaced
pane failures end unsettled waits with `agent_unavailable` and a `delivery_error`
while retaining the request for recovery. Temporary readiness waits and an
unavailable native poll do not prove terminal failure.

## Run-scoped permission bypass

`bus --yolo` and `./run dev --yolo` add a permission-bypass flag to every
work-room worker and MASTER orchestrator, whether added through the UI or
`bus agent add`. `bus resume --last --yolo` (also
`./run dev resume --last --yolo`) applies it to resumed agents and new additions.
The startup flag can precede `resume` or follow its selector.

| Provider | Bus adds | Existing aliases suppress the added copy |
| --- | --- | --- |
| Claude Code | `--dangerously-skip-permissions` | `--dangerously-skip-permissions` |
| Codex | `--yolo` | `--yolo`, `--dangerously-bypass-approvals-and-sandbox` |
| Cursor | `--force` | `--force`, `--yolo`, `-f` |
| Kimi | `--yolo` | `--yolo`, `-y` |

Evidence checked locally on 2026-10-16: Claude Code 2.1.301 `--help` describes
`--dangerously-skip-permissions` as bypassing permission checks. Codex 0.163.0
`--help` documents `--dangerously-bypass-approvals-and-sandbox`; its hidden
`--yolo` alias is accepted by `codex --yolo --version`. Cursor
2026.10.14-0f9edde `--help` documents `-f, --force` as allowing commands unless
explicitly denied and `--yolo` as its alias. Kimi's Bus bypass flag is
`--yolo`; an existing `--yolo` or `-y` suppresses that added copy. `--auto`
cannot be combined with either flag or with a Bus `--yolo` run.

The existing restriction on adding new Codex orchestrators still applies;
saved Codex MASTER agents receive the bypass flag when resumed with `--yolo`.

This is off by default and belongs only to the current Bus daemon's run.
Bus never writes its generated bypass flag into `launch-options.json`.
Quit and resume without `--yolo` to return to normal permissions; explicit
provider options in an agent's own `--args` still replay as requested.
During a yolo run, Bus omits Codex's mutually exclusive `-a` /
`--ask-for-approval` (including attached values) and `--approve-for-me` from
effective argv so Codex can start with bypass enabled. Their original tokens
remain saved and replay on a later normal run. Compatible options such as
`--sandbox` remain in place. The private run marker is not exported into panes.
Attaching to a running daemon with a different `--yolo` setting is refused;
quit its UI or use `bus stop`, then resume with the desired setting.
Without this startup flag, launch behavior and orchestrators' handling of
worker permission dialogs are unchanged.

## Provider updates

Bus disables provider self-updates on fresh room launches and saved-session
resumes: Codex gets `-c check_for_update_on_startup=false`, Cursor gets
`--disable-auto-update`, and Claude gets `DISABLE_AUTOUPDATER=1` when that
environment setting is absent. An explicit inherited Claude setting is retained;
Claude user/project settings can override the inherited environment. Kimi gets
`cache_expiry_hint = false` and `[upgrade] auto_install = false` in `tui.toml`
inside that agent's Bus-owned home (`KIMI_CODE_HOME`, the callback spool's
`kimi-home`). `cache_expiry_hint = false` also disables Kimi's "Cache expired"
chooser. Bus does not modify the developer's `~/.kimi-code`, user configuration,
or the shared provider installation.

Update providers outside Bus after closing their panes. An update chooser
remains blocked for an operator; Bus never selects “Update now”, interrupts an
installer on a timer, or relaunches a provider to complete its update.

## Per-agent arguments

The add-agent form's **Additional launch args** field and `bus agent add --args`
accept provider arguments as literal argv. Quotes group values and are removed;
Bus performs no shell expansion. Permission, sandbox, configuration, workspace,
model and unknown provider options pass through, in their original token order.
For example:

```text
codex:  -c 'model_reasoning_effort="high"' --sandbox workspace-write --ask-for-approval on-request
claude: --dangerously-skip-permissions --permission-mode bypassPermissions
cursor: --yolo --force --sandbox disabled --approve-mcps
kimi:   -m MODEL --skills-dir PATH
```

Bus saves the original user tokens in the launch's `launch-options.json` and
replays permission/configuration options on resume. Without Bus `--yolo`, it
adds no bypass flag and never removes an original one. A bound conversation has
already consumed its initial prompt and native session selector, so those one-time inputs are not
sent again. Options after an initial prompt are retained. An unstarted launch
retains all initial input. Unknown option arity preserves the remaining tokens
without guessing which of them are values or one-time input.

Kimi's new session receives Bus's system prompt as `--agent-file`, written to
`kimi-agent.md` in the callback spool. Kimi keeps that file for the session, so
resume does not pass `--agent-file` again. After Bus owns the conversation it
resumes with `--session <id>`. A user `--session` or `-S` is rejected; adopting
an external Kimi session is unsupported. Resume replays the saved user options,
drops a saved `--agent-file` or `--session`, and then adds Bus's own `--session`.
An explicit `--yolo` or `-y` in those saved options is replayed. The generated
Bus `--yolo` flag is not written into `launch-options.json`.

An unstarted Kimi pane has no session yet. Its saved argv is `/usr/bin/env`,
`KIMI_DISABLE_OAUTH_LOCK=0`, `KIMI_CODE_HOME=<absolute private home>`, then the
`kimi` executable and any user options. Restore accepts that prefix, requires
the executable to be named `kimi`, and refuses `--session`, `-S`, `--continue`,
`-c`, `--prompt`, and `-p` on that unstarted argv. User options remain owned by
`launch-options.json`. The private home is the per-agent directory Bus created
under the callback spool. It is never the developer's `~/.kimi-code`.

Bus separately supplies its capture arguments (`--no-daemon` for Codex and
`--settings <capture-file>` for Claude) and the saved conversation selector.
When the user supplies Codex `--no-daemon`, Bus omits its generated copy:
Codex 0.162.0 rejects the same flag appearing twice.
An explicit UUID resume selector can be normalized and reserved for ownership;
on add, native pickers, names and other selectors remain the provider's input.
Bus-generated capture and orchestration options precede a literal `--` tail,
preserving the original user token order and literal prompt.

Bus does not validate provider option names, required values or choices. Unknown
syntax passes through; when its arity is unclear, Bus stops inspecting it rather
than guessing that a value is a command or selector. Known option values and
the literal tail after `--` are never treated as Bus mode flags. The provider
remains responsible for accepting its own syntax and configurations.

Bus rejects only these evidenced launch incompatibilities, when recognized in
command/option position:

| Provider | Arguments | Why |
| --- | --- | --- |
| Codex | `exec`, `e`, `review` | These run noninteractively instead of hosting the persistent interactive terminal used for room prompts. |
| Claude | `-p`, `--print`, `--bg`, `--background` | Print mode exits; background mode returns immediately, leaving Bus without its interactive worker. |
| Claude | `--bare`, `--safe-mode` | These explicitly disable hooks required for session ownership and request completion. |
| Cursor | `-p`, `--print` | These select script/noninteractive output instead of the interactive terminal Bus drives. |
| Kimi | `-p`, `--prompt`, `--agent`, `--agent-file`, `--continue`, `-c`, `--plan`, `--help`, `-h`, `--version`, `-V`, and a leading positional | These select a one-shot prompt, a non-Bus agent file, continue/plan mode, or help/version exit instead of the interactive terminal Bus drives. |
| Kimi | `--session`, `-S` | Adopting an external Kimi session is unsupported. Bus supplies `--session` itself after it owns the conversation. |
| All | A NUL byte inside a token | Operating-system process argv cannot contain NUL. Unclosed quotes or a trailing escape also cannot be tokenized. |

Evidence checked locally on 2026-10-15: `codex --help` (0.162.0) labels `exec`
and its `e` alias, plus `review`, noninteractive; `claude --help` (2.1.300)
documents print-and-exit, background-and-return, and hooks disabled by bare/safe
mode; `cursor-agent --help` (2026.10.14-0f9edde) documents print as noninteractive.
Bus's dependency is in `src/messaging/coordinator/agents.rs` (interactive
`agent.start`), `src/agents/providers/hook_json.rs` (required observation events)
and `src/messaging/coordinator/callbacks.rs` (SessionStart ownership attestation).
These are operational checks, not a permission policy. Configurations that
change hook behavior are still forwarded to the provider.

Resume also verifies Bus's stored ownership, capture manifest and hooks before
reattaching a managed worker. An unstarted Codex record containing a native
session selector cannot be restored as a new empty conversation. These checks
protect conversation identity; they do not filter the saved permission flags.
