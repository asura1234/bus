# Bus delivery-latency QA

## Run contract and setup recipes

- Use only a fresh driver-owned scratch Bus with fake Claude. Never connect to the running Bus, a real provider, global provider configuration, or `target/debug`. Start at 120 columns × 40 rows. The fake agent performs real PTY, composer, hook, persistence and dashboard work; no model thinking is measured.
- Start with pristine scratch data in the default `bus` room. Read-only scratch state, logs, effects and loopback HTTP may corroborate every step. UI actions create/change the data. Record the commit, driver run folder, request/message IDs, endpoint and all timestamp comparisons. A mismatch is FAIL; unavailable required evidence is FAIL, not a timing retry.
- **Create and select the worker:** press Ctrl+N; type `latency-agent`; press Tab, select Claude Code and Enter; press Ctrl+A then Ctrl+K; type the absolute scratch workspace path; complete the highlighted path with Enter, then Tab to optional args; click Add. If hook consent appears, approve only the isolated project. Wait for the fake terminal, press F6, then use Ctrl+P to select exactly `latency-agent` and Esc.
- **Compare phases:** select the completed request in scratch state. Require accepted, queued, picked, native requested, server accepted, writer queued, paste started, exact text written, paste completed, composer owned, Enter sent, Enter written, native confirmed, provider Started, native-final observation and recorded turn-end timestamps. The legacy `reply_captured_at_ms` field records that accepted final callback, not a stored reply; `reply_delivered_at_ms` must stay null because this case supplies no explicit reply. Each exact text/Enter write must be at or before its corresponding runtime completion. Compare timestamps for identically named log events within 2 ms where both exist; coordinator/provider hook observation can be later than the provider event itself and is reported separately.

## LATENCY-01 — Real delivery and dashboard agreement

**Preconditions/setup:** fresh scratch session and the worker created/selected as above.

1. Type `fake:raw-reply LATENCY_OK`, press Enter, and wait for native output `LATENCY_OK` and its request to settle with `complete:true`, `stage:ended`, `reply:null` and no failure reason → that one ended request contains every required phase timestamp in a monotonic-safe breakdown. The exact actor text-write and Enter-write timestamps match their new native log events within 2 ms; queue/native-request markers match their client log events within 2 ms; provider Started, native-final observation and turn settlement are distinct; none is durable publication of a stored reply. Save the request/message IDs and comparison output as evidence.
2. Open Settings and click `Open delivery dashboard` → the recorded open effect names the scratch dashboard URL. GET `/` returns the dark-themed delivery page. Its provider and room tables include p50, p90, p99 and n beside Delivered, Attempted, Pending, Delivery %, Bus failures and External. Those latency cells and the headline Average latency use human units (milliseconds under 1 s, one decimal second under 60 s, then minutes and seconds) and measure send accepted until the agent turn takes the message (`accepted_at` to `picked_at`), not room delivery. The headline shows Delivery success beside that average. Pending and failed share one card. The hourly graph is present and the hourly table is absent. GET `/data` exposes that request's per-provider and per-room `accepted_to_picked` p50, p90, p99 and mean in raw milliseconds, equal to the persisted accepted-to-picked duration for this single sample. The payload has no `end_to_end` series and no `reply_delivered_at` or `reply_captured_at` latency. GET `/latency` and GET `/latency/data` are 404. An empty group is an em dash, not 0. Re-read scratch files to show no dashboard writes or message-content exposure. Save the JSON, effect, comparison output, TUI screenshot and the page's exact dark-theme CSS variables as evidence.

**Pass criteria:** all timestamps and log comparisons match, the delivery table percentiles and the mean agree with the persisted request, empty groups stay an em dash, and the dashboard is read-only.
